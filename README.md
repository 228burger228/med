# 🩺 Ainala Rehab — Платформа безопасной реабилитации (MVP 0.3)

> **Демо (GitHub Pages):** [https://228burger228.github.io/med/](https://228burger228.github.io/med/)  
> **Репозиторий:** [https://github.com/228burger228/med](https://github.com/228burger228/med)

Веб-приложение, которое помогает пациентам безопасно проходить реабилитацию после травм и операций: план упражнений под область и фазу, тренировки с таймером, дневник боли и симптомов с проверкой «красных флагов», восстановительный режим и отчёт для врача. **Все данные хранятся только в браузере (localStorage)** — сервера пока нет.

---

## 🚀 Быстрый старт для разработчика

### 1. Локальная разработка
```bash
npm install
npm run dev        # http://localhost:5173
```

### 2. Сборка и деплой на GitHub Pages
```bash
npm run build      # собирает всё приложение в ОДИН файл docs/index.html
git add docs && git commit -m "chore: rebuild docs bundle" && git push origin main
```

**Как устроен `index.html`:** корневой `index.html` — исходный шаблон Vite (подключает `src/main.jsx`).
GitHub Pages отдаёт корень ветки `main`, поэтому в шаблоне есть маленький скрипт: если страница открыта **без** dev-сервера Vite
(на Pages или двойным кликом по файлу), он перенаправляет на собранный `docs/index.html`.
`docs/index.html` — автономный бандл (JS и CSS встроены через `vite-plugin-singlefile`), работает и по `file://`.
Не забывайте пересобирать `docs/` перед пушем, иначе на Pages останется старая версия.

## ✅ Что сделано в 0.3

### Безопасность пациента
- «Красные флаги» проверяются **в анкете и в дневнике симптомов** (раньше результат детектора в анкете игнорировался); учитываются отрицания («нет одышки»), температура «t 38.5», «под 39».
- Убрана автоматическая задача «Приём обезболивающего» у всех пользователей — лекарства появляются только из календаря самого пациента.
- При боли 7+ тренировки блокируются с рекомендацией связаться с врачом; после тренировки спрашивается боль.
- Медицинские формулировки смягчены до доказательного уровня (коллаген/витамин C, сон, вода), в калькуляторах — дисклеймеры.

### Честность интерфейса
- Нет фиктивного логина, подключения Apple Health/Календаря/уведомлений, пейволла и сообщения «отчёт отправлен». Метки HIPAA/GDPR/152-ФЗ убраны.
- Помощник подписан как справочный (по ключевым словам, не LLM). Лента сообщества заменена на «Истории восстановления» с пометкой «примеры».
- Все показатели (серия, выполнение, график боли, достижения, отчёт врачу) считаются из реальных данных.

### Функциональность и баги
- Главная — дашборд: «Мои показатели» (боль / после ЛФК / выполнение / тренировки), календарь месяца с отметками, «Мои упражнения» на сегодня, «Мой режим» (холод, возвышенное положение, ходьба, белок + назначенные лекарства), карточка фазы. На десктопе — боковая панель, на телефоне — нижняя навигация.
- Таймер тренировки переписан на чистый редьюсер (раньше в StrictMode пропускал подходы и дублировал звуки).
- Сохраняются между перезагрузками: дневник, журнал боли, тренировки, календарь, контакты врача, фото (сжимаются). Экспорт в JSON и удаление всех данных — в профиле.
- Ручной выбор области травмы, если классификатор не распознал описание; дата травмы; единицы (фунты → кг в калькуляторах).
- Отчёт врачу: копирование, печать/PDF, «Поделиться», письмо на email врача.

## 📂 Архитектура проекта

```text
med/
├── index.html                    # Шаблон Vite + редирект на docs/ вне dev-сервера
├── docs/index.html               # Собранное автономное приложение (GitHub Pages / file://)
├── src/
│   ├── App.jsx                   # Состояние (localStorage), навигация, сайдбар
│   ├── screens/                  # Home (дашборд), Onboarding, Exercises, GuidedSession, Progress,
│   │                             # Assistant, Calendar, Doctor, Calculators, Library, Profile
│   ├── components/
│   │   ├── ui/SharedUI.jsx       # Modal (<dialog>), Pill, PainSlider, RedFlagAlert, BodyMap, RedFlagsModal…
│   │   ├── JointAnimation.jsx    # SVG-анимация сустава
│   │   └── PhotoTracker.jsx      # Фото «до/после» со сжатием
│   ├── data/mockData.js          # Упражнения, фазы, режим восстановления, статьи, «красные флаги»
│   ├── services/aiService.js     # Классификатор травмы (прокси VITE_API_PROXY_URL или локальный) и справочный помощник
│   ├── utils/security.js         # Очистка ввода, детектор «красных флагов», хранилище, экспорт
│   ├── utils/stats.js            # Даты, план по фазе, серия, выполнение плана
│   ├── utils/sound.js            # Звуки таймера (Web Audio API)
│   ├── theme/tokens.js           # Палитра и шрифты (Manrope)
│   └── index.css                 # Дизайн-система, раскладка дашборда
├── supabase-schema.sql           # Схема БД + RLS на будущее (пока не используется)
└── .env.example                  # VITE_API_PROXY_URL
```

### Блок 2. Продукт и Клиническая логика

   - Достаточно ли на этапе MVP генерации PDF/Telegram-отчёта со стороны пациента, или нужен отдельный веб-кабинет врача (где реабилитолог по коду пациента сам меняет количество подходов и фазу)?
